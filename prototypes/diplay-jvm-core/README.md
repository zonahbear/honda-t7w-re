# diplay-jvm-core: DiPlay's protocol core on a desktop JVM (prototype)

Compile-only proof that DiPlay's CarPlay receiver core (iAP2, AirPlay/CarPlay session
and crypto, MFi auth clients, Lockdown pairing, Concentus Opus) builds on Linux x64
with a ~70-line Android stub. Findings and the full port plan: [docs/diplay-audit.md](../../docs/diplay-audit.md).

**Status (2026-11-09): compiles (276 DiPlay files, ~56.8k lines, 0 errors) on JDK 21 /
Kotlin 2.2.10 / Gradle 8.14. Nothing was executed.** It is a library: no `main`, no USB, no video, no
Wi-Fi. Compiling proves the APIs line up. It does not prove the code works off Android.

## What's here (all ours)
| Path | Role |
|---|---|
| `build.gradle.kts` | stages the listed DiPlay files from `$DIPLAY_DIR` into `build/` (gitignored) and compiles them with ours |
| `files.txt` | the portable file list, generated by `tools/port_scope.py --shim --seam-dir seams` |
| `shim/android/...` | desktop stand-ins for `android.util.Log`, `android.util.Xml` (kXML2), `android.os.Build`, `android.os.Process` |
| `seams/com/shilapi/...` | our desktop rewrites of DiPlay files that touch Android, with the same package and API (`TcpLiveness`, `OpusEncoderSupport`) |

DiPlay's sources are never copied into this repo. **License:** anything built here links
GPL-3.0 code, so treat this directory and its outputs as **GPL-3.0-or-later**.

## Reproduce (CachyOS)
```bash
sudo pacman -S --needed jdk21-openjdk gradle
git clone https://github.com/shihabal3amri/DiPlay ~/src/DiPlay   # tested at 615b32c
cd prototypes/diplay-jvm-core
# optional: regenerate the list for a newer DiPlay
python3 -I ../../tools/port_scope.py ~/src/DiPlay/shared/src/main/java --shim --seam-dir seams --json /tmp/scope.json
DIPLAY_DIR=~/src/DiPlay gradle --no-daemon compileKotlin compileJava
```
To regenerate `files.txt` from the JSON, keep the `per_file` entries whose `state` is `pure` and strip each key's `java:` prefix. Gradle downloads the Kotlin plugin, Bouncy Castle 1.79, JmDNS 3.6.3 and kXML2 2.3.0 from Maven Central.

## Not ported yet (needs a Linux implementation, ranked)
1. **USB host for the iPhone**: `transport/IphoneUsbHost` and `IphoneCarPlayConfiguration`, on libusb (usb4java or the JDK 22 FFM API). The kernel's `cdc_ncm` driver replaces DiPlay's userspace `NcmUsbBridge`, `Ipv6NcmBridge` and `CarPlayVpnService` completely.
2. **MFi signer**: `LinuxI2cTransport` (rebuild DiPlay's `linux_i2c_jni.c` for x86_64, or use FFM) for `/dev/i2c-N`, or `Ch341UsbHost` on libusb for a CH341 USB-I2C adapter carrying a real MFi chip. **Never use the Carlinkit identity bundled in the DiPlay APK** (decision D8).
3. **Media sink**: `AndroidMediaSink`, swapped for GStreamer or FFmpeg (H.264/HEVC + AAC/ALAC/Opus → PipeWire), plus touch from `evdev`/SDL into `AirPlayHid`.
4. **Wireless**: Bluetooth RFCOMM through BlueZ, Wi-Fi AP through hostapd/NetworkManager, and Bonjour (JmDNS already works on the desktop JVM).
5. **Controller**: `orchestration/CarPlayController` (3.3k lines, deeply tied to Android services). Write a new, slimmer desktop controller instead of porting it.
